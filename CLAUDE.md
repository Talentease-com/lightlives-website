## Project Overview

Light Lives is a charity website built with Next.js 15 (App Router), Payload CMS 3.59+, and Razorpay payment integration. The site features a public-facing frontend for donations and content display, plus an admin panel for content management.

**Tech Stack:**
- Next.js 15 with React 19, Turbopack for dev/build
- Payload CMS 3.59+ with Vercel Postgres adapter
- Razorpay for payment processing
- Cloudflare R2 for media storage via S3 adapter
- Tailwind CSS 4 with custom color system
- Framer Motion (via `motion` package) for animations
- shadcn/ui components (New York style)
- Resend for transactional emails

## Development Commands

## Architecture

### Route Groups

The app uses Next.js route groups to separate concerns:

```
src/app/
├── (frontend)/              # Public website - has Navbar/Footer layout
│   ├── layout.tsx           # Root layout with AdminBar, Navbar, Footer
│   ├── page.tsx             # Homepage
│   ├── sponsor/             # Donation pages
│   ├── about/               # About, Team, Programs pages
│   ├── contact/             # Contact form
│   ├── csr/                 # CSR partnership pages
│   └── support/             # Volunteer and careers
│
├── (payload)/               # Payload CMS admin
│   ├── layout.tsx           # AUTO-GENERATED - DO NOT EDIT MANUALLY
│   ├── custom.scss          # Custom admin panel styles
│   └── admin/               # Admin interface
│
└── api/
    ├── newsletter/          # Newsletter subscription endpoint
    └── (note: payment APIs not in codebase currently)
```

**CRITICAL:** The `(payload)/layout.tsx` file is auto-generated by Payload CMS. NEVER manually edit this file. For admin customization, modify `payload.config.ts` admin options or `custom.scss`.

### Payload CMS Data Architecture

**Collections** (many items, stored in `src/collections/`):
- `Users` - Admin authentication
- `Media` - File uploads to Cloudflare R2
- `Payments` - Donation records with auto-receipt generation
- `Impacts` - Impact statistics (homepage)
- `Testimonials` - User testimonials
- `TeamCarouselImages`, `LeadershipTeam`, `AdvisoryBoard` - Team pages
- `HeroCarouselImages`, `VideoGallery`, `VerticalGallery`, `GeneralGallery` - Media galleries
- `ContactSubmissions`, `CareerApplications`, `NewsletterSubscribers` - Form submissions
- `CSRInquiries`, `Partners` - CSR partnership data
- `OurJourney` - Timeline milestones

**Globals** (single instance, stored in `src/globals/`):
- `EmailSettings` - Email configuration
- `SocialSettings` - Contact info, social media URLs, footer description
- `FooterLinks` - Dynamic footer navigation by category
- `PageImages`, `PageVideos` - Reusable media assets

### Data Fetching Pattern

**ALWAYS use this pattern for fetching Payload data:**

```typescript
import { getPayload } from 'payload'
import config from '@payload-config'  // Uses auto-generated alias
import { cache } from 'react'

// Collection fetch pattern
export const getImpactData = cache(async () => {
  const payload = await getPayload({ config })
  const impacts = await payload.find({
    collection: 'impacts',
    where: { isActive: { equals: true } },
    sort: 'displayOrder',
    limit: 100,
  })
  return impacts.docs
})

// Global fetch pattern
export const getSocialSettings = cache(async () => {
  const payload = await getPayload({ config })
  return await payload.findGlobal({ slug: 'social-settings' })
})
```

**Key principles:**
- Wrap in `cache()` for React Server Component deduplication
- Import config from `'@payload-config'` (NOT `'@/payload.config'`)
- Use Payload's query API with `where`, `sort`, `limit`
- See `src/lib/payload/fetch.ts` for all fetch helpers

### Cache Revalidation Pattern

Globals that affect shared layouts use `afterChange` hooks:

```typescript
import { revalidatePath } from 'next/cache'
import type { GlobalAfterChangeHook } from 'payload'

export const revalidateFooter: GlobalAfterChangeHook = async ({ doc, req }) => {
  try {
    revalidatePath('/', 'layout') // Revalidates root layout across all pages
    req.payload.logger.info({ msg: 'Footer content updated - cache revalidated' })
  } catch (error) {
    req.payload.logger.error({ msg: `Error revalidating: ${error.message}` })
  }
  return doc
}
```

Apply this pattern when creating globals that affect site-wide UI (header, footer, settings). See `src/globals/hooks/revalidateFooter.ts` for reference.

### Logging System

All collections and globals are wrapped with logging helpers in `payload.config.ts`:

```typescript
import { withCollectionLogging, withGlobalLogging } from './lib/payload/hooks/logging'

collections: [
  withCollectionLogging(Users),
  withCollectionLogging(Media),
  // ...
]

globals: [
  withGlobalLogging(SocialSettings),
  // ...
]
```

This provides colored console logs for all CRUD operations. See `src/lib/payload/hooks/logging.ts` for implementation.

## Payment Integration

### Razorpay Flow

1. User fills form in `DonationForm.tsx`
2. Frontend calls `/api/payments/create-order` (not in current codebase)
3. `PaymentGateway.tsx` hook handles Razorpay checkout
4. Verify payment via `/api/payments/verify`
5. Webhook updates status via `/api/payments/webhook`
6. Receipt auto-generated via `beforeChange` hook

**Critical payment patterns:**

```typescript
// ALWAYS convert amounts to paise (multiply by 100) for Razorpay
const amountInPaise = amount * 100

// Receipt generation pattern (in Payments collection beforeChange hook)
if (operation === 'create' && !data.receiptNumber) {
  const timestamp = new Date().toISOString().slice(0, 10).replace(/-/g, '')
  const randomSuffix = Math.random().toString(36).substr(2, 4).toUpperCase()
  data.receiptNumber = `LL${timestamp}${randomSuffix}` // e.g., LL20251024AB3D
}

// Payment status state machine
type PaymentStatus = 'idle' | 'processing' | 'success' | 'error'

// Payment types
type PaymentType = 'onetime' | 'recurring' | 'upi'
```

**Amount validation:**
- Minimum: ₹1
- Maximum: ₹10,00,000

See documentation in `docs/PAYMENT_INTEGRATION.md` for full details.

## Development Patterns

### Component Conventions

**When to use 'use client':**
- Forms and form handlers
- Animations (Framer Motion)
- React hooks (useState, useEffect, etc.)
- Event handlers (onClick, etc.)
- Browser APIs

**Server Components (default):**
- Layouts
- Static content
- Data fetching from Payload

**Import structure:**
- Use path alias: `@/components/[Category]/ComponentName`
- Categories: `Home/`, `Layout/`, `Sponsor/`, `Admin/`, `Contact/`, `Support/`, `Team/`, `Programs/`, `CSR/`, `Volunteer/`, `ui/`

### Styling Conventions

**Brand Guidelines:**
- **NO BORDER RADIUS:** Always use `rounded-none` or `borderRadius: 0` on all components
- **Color system:** Use CSS custom properties from `globals.css`
  - `bg-primary`, `text-secondary`, `border-tertiary-200`
  - Colors: `primary`, `secondary`, `tertiary` with -50 to -900 variants
- **Glassmorphism:** `backdrop-blur-[5px]` for forms and cards
- **Typography:** Geist Sans (body), Geist Mono (code) via `next/font/google`

### Animation Patterns

**IMPORTANT:** Import from `motion/react`, NOT `framer-motion`:

```tsx
import { motion } from 'motion/react' // ✅ Correct
import { motion } from 'framer-motion' // ❌ Wrong

// Standard page entry
<motion.div
  initial={{ opacity: 0, y: 20 }}
  animate={{ opacity: 1, y: 0 }}
  transition={{ duration: 0.8 }}
>

// Stagger children
<motion.div
  initial="hidden"
  animate="visible"
  variants={{
    visible: { transition: { staggerChildren: 0.1 } }
  }}
>
```

### Adding shadcn/ui Components

```bash
npx shadcn@latest add [component-name]
```

**CRITICAL:** After adding, apply `rounded-none` class to all shadcn components to match brand guidelines.

`tsconfig.json` defines two critical path aliases:

```json
{
  "paths": {
    "@/*": ["./src/*"],
    "@payload-config": ["./src/payload.config.ts"]
  }
}
```

**ALWAYS** use `@payload-config` when importing Payload config, NOT `@/payload.config`.

### Next.js Configuration

`next.config.ts` uses `withPayload()` wrapper for Payload integration:

```typescript
import { withPayload } from "@payloadcms/next/withPayload";

const nextConfig: NextConfig = {
  images: {
    remotePatterns: [
      // Cloudflare R2 custom domain
      { protocol: 'https', hostname: 'cdn.lightlives.org', pathname: '/**' },
      // ... other patterns
    ],
    minimumCacheTTL: 2678400, // 31 days - reduces image optimization API calls
  },

export default withPayload(nextConfig);
```

## Common Tasks

### Adding a New Collection

1. Create schema file: `src/collections/YourCollection.ts`
2. Define collection config (see existing collections for examples)
3. Import and wrap in `payload.config.ts`:
   ```typescript
   import { YourCollection } from './collections/YourCollection'

   collections: [
     withCollectionLogging(YourCollection),
     // ...
   ]
   ```
4. Run `pnpm generate:types` to update TypeScript types
5. Create fetch helper in `src/lib/payload/fetch.ts`:
   ```typescript
   export const getYourCollection = cache(async () => {
     const payload = await getPayload({ config })
     const items = await payload.find({
       collection: 'your-collection',
       where: { isActive: { equals: true } },
       sort: 'displayOrder',
     })
     return items.docs
   })
   ```

### Adding a New Global

1. Create schema file: `src/globals/YourGlobal.ts`
2. If it affects shared layouts, add revalidation hook:
   ```typescript
   import { revalidateFooter } from './hooks/revalidateFooter'

   hooks: {
     afterChange: [revalidateFooter]
   }
   ```
3. Wrap and import in `payload.config.ts`:
   ```typescript
   globals: [
     withGlobalLogging(YourGlobal),
   ]
   ```
4. Run `pnpm generate:types`
5. Fetch via:
   ```typescript
   const data = await payload.findGlobal({ slug: 'your-global' })
   ```

## Important Notes

### Auto-Generated Files (DO NOT EDIT)

These files are generated by tools and should never be manually edited:
- `src/payload-types.ts` - TypeScript types (run `pnpm generate:types`)
- `src/app/(payload)/layout.tsx` - Payload admin layout
- `src/app/(payload)/admin/importMap.js` - Admin component imports

### Performance Considerations

- **AdminBar warning:** The AdminBar component pings the server on every page load, which can deplete serverless function limits on high traffic sites
- **Static generation:** Use `export const dynamic = 'force-static'` for cacheable pages
- **Image optimization:** Set in `next.config.ts` with 31-day cache TTL to reduce serverless API calls

### Environment Variables

Required for development (copy from `example.env.local`):
- `PAYLOAD_SECRET` - Encryption key for Payload auth
- `POSTGRES_URL` - Vercel Postgres connection string
- `RAZORPAY_KEY_ID`, `RAZORPAY_KEY_SECRET`, `NEXT_PUBLIC_RAZORPAY_KEY_ID`
- `RESEND_API_KEY` - For emails
- `S3_ENDPOINT`, `S3_BUCKET`, `S3_ACCESS_KEY_ID`, `S3_SECRET` - Cloudflare R2
- `NEXT_PUBLIC_APP_URL` - Base URL (default: http://localhost:3000)
- `R2_PUBLIC_URL` - Custom domain for R2 (e.g., https://cdn.lightlives.org)
